## D1. The drawer stays open when you choose firmware (P1, operator finding 1)

**Key points:** A click on "Latest" or a version chip closes the whole drawer. The cause is a stale DOM check in the outside-click handler. The drawer must close only on a deliberate action, and never while it holds unsaved changes.

**Detail:**

Problem. See the Firmware card in the [operator screenshot](ui-review-2026-11-19/updates-panel-operator-2026-11-19.png). A click on any firmware chip collapses the drawer.

Root cause.

1. The chip calls `selectDrawerFw()` (`monitor.html:10021`).
2. `selectDrawerFw()` calls `renderDrawerFirmware()`, which replaces `#drawerFwList.innerHTML` (`monitor.html:10017`). The clicked chip leaves the document.
3. The click bubbles to the document listener "Collapse drawer when clicking outside it" (`monitor.html:9589`).
4. That listener tests `e.target.closest('.bottom-drawer')`. The target is now detached, so `closest()` returns `null`.
5. The listener reads this as an outside click and removes `.open`.

Every control that re-renders its own container on click has the same fault. Today that is the "Latest" chip and each version chip.

Decision. The outside-click listener uses the event path, which the browser fixes at dispatch time. The drawer also stays open while it has unsaved changes.

Spec.

- In the document click listener, replace `e.target.closest('.bottom-drawer')` with `e.composedPath().includes(drawer)`.
- Add `if (drawerDirty) return;` before the drawer closes on an outside click.
- The handle click (`toggleDrawer`) still closes the drawer when it has unsaved changes. The unsaved state stays visible in the bar (D2), so nothing is hidden.
- Add Escape: when focus is in the drawer and `drawerDirty` is false, Escape closes the drawer and returns focus to `#drawerHandle`.
- Test: click "Latest", then a version chip, then "Latest". The drawer stays open after each click.

Files: `updater/templates/monitor.html` (document click listener near line 9589, keydown listener).

## D2. Save moves into the status bar (P1, operator finding 2)

**Key points:** Save and "Unsaved changes" sit at the bottom-left of the open drawer, far from the eye line. The only other cue is a 6 px orange dot in the bar. Move one save cluster to the right end of the status bar, and show it only when there are unsaved changes.

**Detail:**

Problem. See the bottom-left of the [operator screenshot](ui-review-2026-11-19/updates-panel-operator-2026-11-19.png). The operator works in the top right (Firmware card) and the eye never reaches the bottom-left. "Unsaved changes" is `#F59E0B` text, 2.15:1. The bar cue is `.drawer-unsaved-dot`, a 6 px `#F59E0B` dot with only a `title`. In the screenshot it is the small orange dot after "Next window". The Save button uses `--primary` with white text, 3.74:1. When the drawer is closed, Save is not visible at all.

Decision. One save cluster lives in the status bar, right-aligned, before the chevron. It shows only while `drawerDirty` is true. It shows with the drawer open or closed. Remove `.drawer-save-row` and `.drawer-unsaved-dot`.

Layout, desktop (> 768 px):

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [toggle] Auto-Update [II Paused]  82 devices to update · Next window: Tue, Nov 24, 3:00 AM          │
│                                              [✎ Unsaved changes] [Discard] [Save changes]   ▾      │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

At widths where the row fits, the cluster stays on the first row with `margin-left: auto`. It wraps to its own right-aligned row only when space runs out.

Spec.

- Container `.bar-save-cluster`: `display:flex; align-items:center; gap: var(--space-4)` (8 px); `margin-left:auto`; `flex-shrink:0`.
- Unsaved pill: the D4 caution pill. Background `--warning-bg` `#FEF3C7`, text `--warning-text` `#92400E` (6.37:1), border 1 px `#B45309` (5.02:1 on white), radius `--radius-full`, padding 3px 10px, `--text-sm`, weight 600. Icon: pencil `✎` (U+270E), 12 px, before the text. Copy: "Unsaved changes".
- Discard: `.btn .btn-ghost .btn-sm`. Copy: "Discard". Action: set `drawerSettingsLoaded = false`, call `loadDrawerSettings()`, then `clearDrawerDirty()`.
- Save: `.btn .btn-primary .btn-sm`. Fill `--primary-fill` `#0F766E`, white text, 5.47:1. Hover `--primary-fill-hover` `#115E59`, 7.58:1. Copy: "Save changes". While saving: copy "Saving…", `aria-busy="true"`, disabled.
- After a good save: hide the cluster. Show "✓ Saved" in the same slot for 3 s, `--text-subtle` `#374151`, 10.31:1. Reuse `#drawerSavedIndicator`. The Auto-Update toggle already saves at once and uses the same indicator.
- After a failed save: keep the cluster. Replace the pill with the D4 critical pill, copy "Not saved. Try again." Keep Save enabled.
- All three controls carry `.btn`, so `toggleDrawer()` and the drag handler already ignore their clicks.
- Mobile (≤ 768 px): the cluster takes its own full-width row at the bottom of the bar. Pill on the left, buttons on the right. Buttons have `min-height: 44px`.

Files: `updater/templates/monitor.html` (bar markup near line 2966, `.drawer-save-*` CSS near line 2056, `markDrawerDirty`, `clearDrawerDirty`, `saveDrawerSettings`).

## D3. The pause reason shows in full, in its own row (P1, operator finding 3)

**Key points:** The reason is cut to "Scheduled firmware updates are paused for safety qualifi…". The full text exists only in a hover tooltip. Show the full reason in a row of its own under the bar, every time the bar is in a Paused or Firmware hold state.

**Detail:**

Problem. See the top-left of the [operator screenshot](ui-review-2026-11-19/updates-panel-operator-2026-11-19.png). The tooltip shows the full text only on hover. Touch screens never show it.

Root cause. `#barBlockReason` uses `.status-bar-reason` (`monitor.html:2151`): `max-width: 320px; white-space: nowrap; text-overflow: ellipsis`. The reason is `SCHEDULED_ROLLOUT_SAFETY_REASON` in `updater/rollout_gate.py:7`, 160 characters. It also uses `--text-dim` `#9CA3AF`, 2.54:1.

Decision. Move the reason out of the first row into a full-width notice row. The row wraps and never truncates. This decision does not touch `rollout_gate.py`. For the scheduled-updates-off state, D15 sets the copy and the action. The example below shows the old string only to show the layout.

Layout:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ [toggle] Auto-Update [II Paused]  82 devices to update · Next window: Tue, Nov 24, 3:00 AM │
│ ┃ II  Scheduled firmware updates are paused for safety qualification. Complete the       │
│ ┃     rollout safety fixes and bench tests, then have the operator record readiness.     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

Spec.

- New element `#barNotice.status-bar-notice` inside `#drawerHandleLeft`, after the first row. `flex-basis:100%`, so the handle wraps to a second row. `#drawerHandleLeft` gets `flex-wrap: wrap`.
- Content: the same string the bar shows today (`status.safety_block_reason || subtitle`). Remove `#barBlockReason` from the first row. Keep `role="status"`. Keep the toggle's `aria-describedby`, pointed at `#barNotice`.
- Caution tone (badge "Paused"): background `#FFFBEB`, text `--text` `#111827` (16.3:1 on `#FFFBEB`), left border 4 px `#B45309`, pause icon 14 px in `#92400E`.
- Info tone (badge "Firmware hold", and `hold_clear_reason`): background `--info-bg-subtle` `#EFF6FF`, text `#111827` (16.3:1), left border 4 px `--info-strong` `#2563EB` (4.75:1 on `#EFF6FF`), clock icon 14 px in `--info-text` `#1D4ED8`.
- Box: padding 8px 12px, radius `--radius-md`, `--text-base` (13 px), line height 1.45, `white-space: normal`, no `max-width`, no line clamp. Margin top `--space-3` (6 px).
- Hide the row when there is no reason. The Scheduled state keeps "Next: …" in the first row (D6) and has no notice row.
- Keep the `renderQueueStatus` de-duplication rule. `#barQueueReason` shows a reason only when it differs from the notice text.
- `syncDrawerPadding()` must run after the notice shows or hides, so the page bottom padding stays correct.

Files: `updater/templates/monitor.html` (bar markup near line 2952, `.status-bar-reason` CSS near line 2151, scheduler-status render near line 8895).

## D4. One colour-blind-safe state palette (P1)

**Key points:** Status uses five tones. Fill weight, an icon and a text label separate them. Hue only adds to that. Green leaves state colour; "healthy" and "up to date" become neutral with a check mark. Red stays only as a solid fill for critical states, never next to green.

**Detail:**

Problem. Today the Paused badge (`#FEF3C7`) and the selected "Latest" chip (`#CCFBF1`) are both pastel pills. They differ by ΔE 25 for a deuteranope. "Up to date" uses `--success-bg` green. "Blocked" uses `--danger-bg` pink. For the operator these read as one family.

Decision. Use this table for every status pill, badge, notice row and inline status message. Update `UI_STYLE_GUIDE.md` "Semantic colors" to match.

| Tone | Use for | Fill | Text | Border | Icon | Text contrast |
|---|---|---|---|---|---|---|
| Neutral | Off, Up to date, Online, Saved | `#F3F4F6` | `#374151` | none | ✓ for Up to date and Saved; ○ for Off | 9.37:1 |
| Info | Scheduled, Updating, Firmware hold | `--info-bg` `#DBEAFE` | `--info-text` `#1D4ED8` | none | clock, or spinner while updating | 5.49:1 |
| Caution | Paused, Unsaved changes, Address changed, Can't sign in, Needs update | `--warning-bg` `#FEF3C7` | `--warning-text` `#92400E` | 1 px `#B45309` | II pause, ✎, ▲ | 6.37:1 |
| Critical | Failed, Stopped, Offline, Not saved | solid `#B91C1C` | `#FFFFFF` | none | ✕ or ■ | 6.47:1 |
| Control selected | Selected day, chosen firmware, toggle on (D5) | solid `--primary-fill` `#0F766E` | `#FFFFFF` | none | ✓ on chips | 5.47:1 |

Rules.

- Caution and critical differ by fill style (tint with border vs solid), icon and label. In simulation the two fills differ by ΔE 57 (deuteranope).
- Control-selected teal and caution amber differ by ΔE 75 (deuteranope) and by solid vs tint.
- Info blue and caution amber stay apart for all common colour-vision types (ΔE 74 or more between the strong colours).
- Never put green or red text on a white or tinted background to show state.
- Add tokens to `:root`: `--state-neutral-bg #F3F4F6`, `--state-neutral-text #374151`, `--warning-border #B45309`, `--danger-fill #B91C1C`, `--danger-fill-text #FFFFFF`. Keep the `--success*` tokens for the brand mark only. Do not use them for state.
- `.status-bar-badge.current` and `.fleet-chip.active.s-cur` move to the neutral tone with ✓.
- `.status-bar-badge.blocked` moves to the critical tone.

Files: `updater/templates/monitor.html` (`:root` near line 14, `.status-bar-badge.*` near line 2122, `.fleet-chip.*` near line 2349), `UI_STYLE_GUIDE.md`, `docs/ui-principles.md` ("Status, color, and copy").

- Day buttons grow from `--text-2xs` (10 px) to `--text-sm` (12 px). Padding 4px 8px.

Files: `updater/templates/monitor.html` (`.toggle*` near line 353, `.drawer-day-btn*` near line 1821, `.drawer-fw-chip*` near line 1906), `static/common.css` (toggles on setup pages, if any).

## D15. Scheduled-updates-off message says the state and gives the action (P1, operator finding 4)

**Key points:** The old message names internal work the operator cannot see ("rollout safety fixes and bench tests"). It does not say that manual updates still work. "Record readiness" is not a control anywhere. The notice row must say the state in plain words, give the pending count and the next window, and offer one action: "Turn on scheduled updates…". The action opens a confirmation that shows the window, the pending count and the scope.

**Detail:**

Problem. Operator comment on [#848](https://github.com/sixtyops/manager/issues/848), and the tooltip in the [operator screenshot](ui-review-2026-11-19/updates-panel-operator-2026-11-19.png). The text came from `SCHEDULED_ROLLOUT_SAFETY_REASON` in `updater/rollout_gate.py:7`.

Current state of [#778](https://github.com/sixtyops/manager/pull/778) (open at review time). It changes the backend string to "Scheduled updates are off for this network until an admin turns them on. Manual updates still work." It adds a second toggle, "Scheduled updates", in the Schedule column, next to the Auto-Update toggle in the bar. It adds a confirmation with scope and next window, but no pending count.

Decision. Keep the #778 backend string and the #778 confirmation helpers. Change three things:

1. The D3 notice row carries the state and the action. The operator sees it without opening the drawer.
2. The Schedule column shows state as text plus a button, not a second toggle. Two toggles side by side ("Auto-Update" on, "Scheduled updates" off) read as a contradiction.
3. The confirmation adds the pending count, the window days and hours, and the update order.

Bar badge in this state. Caution tone (D4), icon ○, copy "Scheduled off". It replaces "Paused". "Paused" stays for weather, time and other block reasons.

Notice row in this state. Caution tone from D3. The UI picks this copy when `status.safety_block_reason` is set. It does not show the raw backend string in this state.

```
┌────────────────────────────────────────────────────────────────────────────────────────────────┐
│ [toggle] Auto-Update [○ Scheduled off]  82 devices to update · Next window: Tue, Nov 24, 3:00 AM │
│ ┃ ○  Scheduled updates are off. Manual updates still work.            [Turn on scheduled updates…] │
│ ┃    Turn on scheduled updates to let Manager update 82 devices in the maintenance window.       │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
```

Copy, notice row:

- Line 1, weight 600: "Scheduled updates are off. Manual updates still work."
- Line 2, normal: "Turn on scheduled updates to let Manager update N devices in the maintenance window." Use "1 device" for one. When N is 0: "Turn on scheduled updates to let Manager update devices in the maintenance window when new firmware is selected."
- Admin: button "Turn on scheduled updates…", `.btn .btn-sm .btn-primary`, right-aligned in the row, vertically centred. The ellipsis says that a confirmation follows.
- Operator and viewer: no button. Line 2 ends with: "Only an admin can turn them on."
- Mobile (≤ 768 px): the button moves under the text, full width, `min-height: 44px`.

Schedule column (replaces the #778 toggle row):

- Off: label "Scheduled updates", value "Off" in the caution pill, button "Turn on…" (`.btn .btn-sm`). Admin only. Others see the pill and no button.
- On: value "On" in the neutral pill with ✓, button "Turn off…" (`.btn .btn-sm .btn-ghost`). Admin only.
- Both buttons call the existing `toggleScheduledUpdates()` from #778.

Confirmation to turn on (the #778 `showConfirmDialog`, `--modal-sm`):

- Title: "Turn on scheduled updates?"
- Body, one fact per line:
  - "Manager updates N devices to the selected firmware, one device at a time."
  - "Window: Tue, Wed, Thu, 3 AM to 4 AM (network time)." Build from `schedule_days`, `schedule_start_hour`, `schedule_end_hour` and the network time zone #778 already reads.
  - "Next window: Tue, Nov 24, 3:00 AM."
  - "Scope: <scope.summary>." Keep the #778 scope list region under the body.
  - "Order: CPEs, then APs, then switches. A failure stops the queue."
  - "Manual updates are not affected."
  - Only when Auto-Update is off: "Auto-Update is off. Turn it on too, or no window starts."
- Buttons: "Cancel" (`.btn-ghost`, left, initial focus), "Turn on scheduled updates" (`.btn-primary`, right).
- After success: the notice row hides, the badge returns to its normal state, and the bar shows "✓ Saved" (D2 slot). Toast copy from #778 stays: "Scheduled updates are on."

Confirmation to turn off:

- Title: "Turn off scheduled updates?"
- Body: "Manager starts no new scheduled update. A device that is already updating finishes. Manual updates still work."
- Buttons: "Cancel", "Turn off scheduled updates" (`.btn-primary`; this is not a destructive action).

Wording rules. Do not name internal work items, bench tests, or "readiness" in UI text. "Scheduled updates" is the one term for this state. "Auto-Update" stays the name of the bar toggle.

Scope. This decision changes copy, layout and control type only. It does not change the setting key (`scheduled_rollout_safety_ready`), the admission check, the audit log entry, or the role rule in #778.

Files: `updater/templates/monitor.html` (#778 Schedule row, `renderScheduledUpdatesToggle`, `toggleScheduledUpdates`, bar badge map near line 8919, D3 notice row). `updater/rollout_gate.py` keeps the #778 string.
